## 一、坏代码场景

```csharp
// 玩家受到伤害
public void TakeDamage(int amount)
{
    hp -= amount;  // 扣血
    if (hp <= 0)  // 死了
    {
        // 掉落物品
        DropLoot();
        // 更新排行榜
        UpdateLeaderboard();
        // 播放死亡动画
        PlayDeathAnim();
        // 通知任务系统
        QuestSystem.OnKill(this);
    }
}
```

## 二、问题（2026-08-14 布置）

1. 这些注释在撒谎吗？哪几行注释说了**代码没说**的事？哪几行只是重复代码？（注释唯一的正当理由：解释代码说不清的事）
2. 如果需求变了（排行榜下线），你会删掉 `UpdateLeaderboard()`——但注释「更新排行榜」还在。**后人信注释还是信代码**？这类撒谎注释叫什么？
3. 什么注释才是好注释？（提示：代码自解释时，注释是噪音）

## 三、你的回答（2026-08-14，同步自 00-我的回答.md）

1. 没有撒谎；扣血死了（重复代码）| 掉落、更新排行榜、播放死亡动画、通知任务系统
2. 更应该信代码；不清楚这类撒谎注释叫什么？
3. 注释代码无法说明的事情，比如做算法时的特殊操作

## 四、标准解（2026-08-14）

### Uncle Bob 坏注释清单（《代码整洁之道》第 4 章，对应用户场景）
- **冗余注释（Redundant）**：重复代码已说的——本场景 8 行全中（「扣血」「死了」「掉落物品」……方法名已自解释）
- **误导性注释（Misleading）**：代码变注释没变——「更新排行榜」功能下线后
- 喃喃自语（Mumbling）、循规式（Mandated 强制加注释）、日志式（Journal——git 已代劳）、噪音（Noise）——其余四种

### 好注释（值得留，只这四类）
1. **解释意图 Why**：算法为什么这么选（不是怎么做的）
2. **警示后果**：「此方法非线程安全」「勿改此常量」
3. **TODO 带负责人+日期**：`// TODO: skyrim 2026-08-20 接排行榜`
4. **公共 API 文档**（XML doc）与法律信息

### 场景标准答案
8 行注释全删——代码本身已自解释；若担心 `Math.Min` 防溢出不明显，可留一行 Why：「// 保证回血不超上限（治疗叠加场景曾溢出）」
