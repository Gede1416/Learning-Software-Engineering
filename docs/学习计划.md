# 软件工程学习路线

> 体系：Milo Yip《游戏程序员学习之路》"软件开发"板块
> 开始日期：2026-07-19
> 教学方式：苏格拉底式 + 游戏场景绑定 + 作业驱动

---

## 核心教材（按教学优先级）

1. 《敏捷软件开发：原则、模式与实践》— Robert C. Martin
2. 《重构：改善既有代码的设计》— Martin Fowler
3. 《代码整洁之道》— Robert C. Martin
4. 《修改代码的艺术》— Michael Feathers
5. 《设计模式》GoF + 《Head First 设计模式》

---

## 四阶段总览

```
阶段一：SOLID 原则 ──── 「这个设计对不对？」
阶段二：设计模式 ──── 「这个场景用什么模式？」
阶段三：重构 ──────── 「这坨烂代码怎么安全改？」
阶段四：整洁+遗留 ──── 「怎么防止写烂？烂了怎么救？」
```

## 阶段三：重构 🚧（进行中，2026-08-03 开始）

> 教材：《重构：改善既有代码的设计（第 2 版）》Martin Fowler
> 阶段问题：「这坨烂代码怎么安全改？」
> 结构：三轮共 15 天（坏味道×手法 → 结构性坏味道 → 重构工作流），作业全部 5-10 分钟
> 每日流程：苏格拉底坏代码（≤30 行）→ 回答 → 标准解 → ≤20 行游戏场景作业 → git 提交

### 第一轮：最常踩的坏味道（Day 1-11）

| Day | 坏味道 | 核心手法 | 游戏场景 | 核心问题 | 跨书联动 |
|-----|--------|----------|----------|----------|----------|
| 1 ✅ | 神秘命名 Mysterious Name | 重命名 Rename | AI 管理器命名 | 名字在撒谎，搜索崩盘 | 整洁之道·有意义的命名 |
| 2 ✅ | 重复代码 Duplicated Code | 提炼函数 Extract Function | 两种敌人死亡结算 | 改一处漏一处 | 策略模式的边界 |
| 3 ✅ | 过长函数 Long Function | 提炼函数/内联 | 玩家升级结算（八件事） | 一坨代码怎么拆 | SRP（函数级） |
| 4 ✅ | 过长参数列表 Long Parameter List | 引入参数对象 | 技能释放 8 参数 | 参数一多就出错 | 重构与设计模式对应 |
| 5 ✅ | 全局数据+可变数据 Global/Mutable Data | 封装变量 | 全局分数 / 单例音量 | 谁改了我的数据 | 单例模式的代价 |
| 6 ✅ | 发散式变化+霰弹式修改 Divergent Change / Shotgun Surgery | 搬移语句/函数 | 加一个新英雄要改 N 个文件 | 一个变化 N 处修改 | SRP / OCP |
| 7 ✅ | 依恋情结 Feature Envy | 搬移函数 Move Function | 伤害计算乱摸别人的字段 | 它为什么用别人的数据 | 数据封装 |
| 8 ✅ | 数据泥团+基本类型偏执 Data Clumps / Primitive Obsession | 引入参数对象/封装记录 | 坐标三兄弟、金币 float/int 混用 | 原始类型满天飞 | 值对象 |
| 9 ✅ | 重复的 switch+循环 Repeated Switches / Loops | 以多态取代条件/以管道取代循环 | 怪物类型 switch、背包手写 for | 每个新类型都要改 switch | 策略/状态模式 |
| 10 ✅ | 消息链+中间人 Message Chains / Middle Man | 隐藏委托/移除中间人 | `player.GetParty().GetLeader()…` | 一路点下去会断 | 迪米特法则/外观 |
| 11 ✅ | 大类+惰性元素 Large Class / Lazy Element | 提炼类/内联 | 3000 行 GameManager | 一个类什么都干 | SRP |

### 第二轮：结构型坏味道（Day 12 收尾）

| Day | 坏味道 | 核心手法 | 游戏场景 | 核心问题 | 跨书联动 |
|-----|--------|----------|----------|----------|----------|
| 12 ✅ | 异曲同工的类+纯数据类+被拒绝的馈赠 Alternative Classes / Data Class / Refused Bequest | 函数改名/接口/继承改组合 | Boss/精英结算长得不一样 | 像 vs 是 | LSP / ISP |

### 第三轮：让重构安全的元知识（Day 13-15）

| Day | 主题 | 核心内容 | 游戏场景 | 核心问题 | 跨书联动 |
|-----|------|----------|----------|----------|----------|
| 13 ✅ | 重构与设计模式的映射 | 条件→多态、提炼类→组合、观察者 | 全套作业回顾 | 重构到哪里是头 | GoF 全表 |

## 阶段四：代码整洁 + 遗留代码 🚧（2026-08-09 开始）

> 教材：《代码整洁之道》Uncle Bob + 《修改代码的艺术》Feathers
> 阶段问题：「怎么防止写烂？烂了怎么救？」
> 结构：三轮共 12 天（整洁之道 → 干净地写 → 遗留代码），作业全部 5-10 分钟

### 第一轮：整洁之道（Day 1-5）

| Day | 主题 | 核心内容 | 游戏场景 | 核心问题 | 跨书联动 |
|-----|------|----------|----------|----------|----------|
| 1 ✅ | 有意义的命名 | 名副其实、避免误导、搜索友好 | 技能/存档命名陷阱 | 名字在撒谎 | 重构·神秘命名（Day 1） |
| 2 ✅ | 函数 | 短小、单一职责、参数少、无副作用 | 战斗结算函数 | 函数多大合适 | 重构·过长函数/参数列表 |
| 3 ✅ | 注释 | 注释是不得已、注释会撒谎 | 存档格式魔法注释 | 代码能自解释吗 | 重构·注释坏味道 |
| 4 ✅ | 格式 | 垂直/水平格式、新闻报式 | 存档系统代码风格 | 格式算不算事 | 团队规范 |
| 5 ✅ | 对象与数据结构 | 封装 vs 暴露、数据/行为分离 | 玩家属性/配置表 | 数据该藏起来吗 | 重构·纯数据类 |

### 第二轮：干净地写代码（Day 6-9）

| 7 ✅ | 边界 | 第三方代码封装（Learning Tests） | 广告/支付 SDK | 边界谁负责 | 适配器模式 |
| 8 | 单元测试整洁 | 测试可读性、F.I.R.S.T. | 存档系统测试 | 测试也是代码 | 重构·测试工作流 |
| 8 ✅ | 单元测试整洁 | 测试可读性、F.I.R.S.T. | 存档系统测试 | 测试也是代码 | 重构·测试工作流 |
| 9 | 类与系统 | 类要小、依赖注入、透明 | 系统管理器/入口 | 类多大合适 | SRP / DIP |
